# DeepSeek 适配建议

适合场景：代码、数学推理、中文分析、长问题拆解、低成本批量评测。

## Prompt 建议

- 复杂任务先要求“先分析任务，再输出结果”，但生产输出中避免展示完整推理链。
- 代码任务要明确语言、框架、测试方式和输出范围。
- JSON 输出要强调“只输出 JSON，不要 Markdown 代码块”。
- 对事实类问题明确是否允许使用外部资料；没有资料时要求说明不确定。

## 示例

```text
你是资深后端工程师。请根据 GitHub Issue 生成修复方案。

要求：
- 先判断问题类型：Bug、性能、兼容性、文档、测试。
- 输出根因假设、排查步骤、修改方案、回归测试。
- 不要编造不存在的文件名或 API。
- 如果信息不足，列出需要补充的日志或代码片段。
```
